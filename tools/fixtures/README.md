# Fixtures

Four sample scenes under `public/fixtures/<id>/`, used by the "Open sample" menu and by `tests/ingest`.

| id | model file | made by |
|---|---|---|
| `enclosure` | `enclosure.step` | `make_models.py` (build123d) |
| `chassis` | `chassis.glb` | `make_models.py` (trimesh) |
| `arm3` | `arm3.urdf`, `meshes/gripper_base.stl` | URDF written by hand; STL by `make_models.py` |
| `arm-cad` | `arm-cad.step`, `axes.json` | `make_models.py` (build123d); axes computed from the placement transforms |

Each scene also has `design.json` and `expected.json`, and `public/fixtures/index.json` lists them all. design.json, expected.json and index.json are generated by `make-designs.ts` from the model files through the app's own importer.

## Regenerate everything

From the repository root (Git Bash shown; in PowerShell use backslashes for the venv path):

```sh
# once: Python 3.12 venv with pinned packages
py -3.12 -m venv .venv
.venv/Scripts/python.exe -m pip install -r tools/fixtures/requirements.txt

# models: STEP, GLB, STL
.venv/Scripts/python.exe tools/fixtures/make_models.py

# designs, expected values, index.json (needs `npm install` done)
npx tsx tools/fixtures/make-designs.ts

# check
npx vitest run tests/ingest
```

The STEP writer puts a timestamp in the file, so regenerating `enclosure.step` changes its SHA-256 and therefore `design.json`. Always run `make-designs.ts` after `make_models.py`, and commit the results together.

URDF lengths are metres, as URDF requires, and the STL is written in metres too; the importer converts to millimetres. glTF is written Y-up as the glTF specification says; the importer rotates it to Z-up.
